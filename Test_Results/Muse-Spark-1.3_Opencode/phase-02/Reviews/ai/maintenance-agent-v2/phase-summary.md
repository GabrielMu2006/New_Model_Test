## 3. 逐题要点

### task-16 鹈鹕骑车动画 SVG（85）

- **成立**：42 个 SMIL 动画元素；暂停后间隔 800 ms 的两次截图逐像素相同且状态文本为 `paused`，恢复后继续变化 → 暂停/继续是**整体冻结**而非部分元素停摆 ✅；单文件、零外部依赖；`viewBox`、`<title>`、`<desc>`、`role`、`aria-label` 齐全。
- **证据薄弱**：题目第一条要求是「多周期下轮/曲柄/踏板/脚/腿相位一致、无脱脚、无曲柄跳变、无断肢」。模型自述以两段 IK 每 4° 烘焙进 SMIL（弦误差 <0.1 px），本次只有**单帧视觉**支持（脚在踏板上、腿无断裂），未逐帧独立测量。
- **自述限制**：以 `<img>` 嵌入时内联脚本不执行、暂停按钮无效。

### task-17 机械腕表机芯（88）

- **独立测量**：1.5 s 内 29 个带 `rotate()` 的元素在转，**14 顺 / 15 逆** → 存在反向转动对，符合啮合齿轮反向 ✅；角速度最快 −179.3°/1.5 s、最慢约 2.1°/1.5 s → 不存在「所有齿轮同速」的错误 ✅；约 ±2°/1.5 s 的小幅净位移元素与摆轮往复运动一致。
- **成立**：暂停冻结、恢复连续、速度 1 → 2.5 后画面仍连续；控制台零错误；机芯各部件有文字标注（BARREL · MAINSPRING / ESCAPE / PALLET / BALANCE / THIRD / FOURTH / 18000 VPH）。
- **未验证**：齿面是否真正接触（仅视觉描述为分层示意图，可见约 7 个齿轮体）；摆轮摆幅与擒纵相位；模型自述冲量瞬间的齿面滑动被时间平均平滑掉。

### task-18 鲁布·戈德堡机关（88）

- **独立测量**：`#hudTime` 在暂停后由 1.62 s 保持 1.62 s，且 **canvas 截图逐像素不变** ✅；Step 1 frame → +0.01 s，Step 0.5 s → 恰好 **+0.500 s** ✅；Reset → 0.00 s 且 HUD 回到 `Ready — press Start` ✅；一次连续运行观测到 `1/8 → 2/8 → 6/8 → 7/8 → Complete (t=11.2s)` ✅。
- **成立**：画布标注 S1 RELEASE → S8 FINISH 共 8 阶段，并明示每个阶段由接触/位置/动量触发而非定时器；含 0.1× 慢速与逐帧步进，正是题目要求的检查手段。
- **未验证**：只跑通 1 次 + 重置 1 次（重复性样本不足）；跨视口与跨帧率鲁棒性；阶段间触发关系未逐帧核验。

### task-19 交互式太阳系（88）

- **独立测量**：暂停后 `#sim-date` 冻结（Day 38.7 → 38.7）✅；画布变化像素比例由运行时的 **1.41%** 降到 **0.32%**（暂停 2.5 s 后仍 0.31%）→ **模拟时间已停止**，残余变化为背景星野重绘，**画布并非完全静止**；默认 20.0 days/sec 与最大 300 days/sec 两档日期都连续推进 ✅。
- **成立**：太阳 + 8 行星 + 地球月球 + Io/Europa/Ganymede/Callisto；轨道/拖尾/标签可切换；缩放、平移、视图切换、天体列表齐备；界面明示调速不重置位置。
- **未验证**：点击选择天体与 Focus planet 的实际效果（探测期间始终 `Nothing selected`）；月球/卫星绕运动母星公转的长期正确性；性能；仅 2D 俯视、无倾角与偏心率（模型自述）。

### task-20 二维连杆设计器（92，本批最高）

- **独立复算（本批最强证据）**：22 次采样（四杆一次运行 + 曲柄滑块一次运行）读取应用关节坐标，复算关节间距离：Rocker P1-B = 180.0（极差 **0.096 px**）、Coupler A-B = 260.0（**0.140**）、ArmA A-C = 141.2（**0.125**）、ArmB B-C = 141.2（**0.167**）→ **刚性连杆长度在运动全程恒定** ✅。应用自报 `max link error ≤ 2.8e-14`、`max slider off-track 0.0e+0`，与复算一致。
- **独立测量**：暂停后画布像素变化率为 **0**；单步改变几何且随后稳定 ✅；Store → New（画布确实改变）→ Recall 后画布与存档前**逐像素相同** ✅。另有 Save/Load file 与 Export/Import JSON。
- **未验证**：单步与连续模拟「等状态一致」未逐点比对（只验证了单步产生改变且随后稳定）；退化轨道/长度导入的自动修复与告警（模型自述）；拖动关节时临时释放电机 pin 的近似（模型自述，应用内已注明）。

## 4. 结论

1. 五题的**暂停/继续、步进、调速、存取**这类可机械验证的交互语义，本次全部经独立测量成立；task-18 的步进精度与 task-20 的连杆长度是两处最硬的独立证据。
2. 五题控制台错误为 0，无外部依赖，无「文件能加载即判定合格」式的宽松结论。
3. 需求符合度的扣分集中在**未被本次取证覆盖**的条款：task-16 的逐帧脚-踏板约束、task-18 的跨视口/帧率鲁棒性、task-19 的天体选择与长期轨道、task-20 的等状态一致性。这些是**取证边界**，不等于缺陷，也不能据此判为通过。
4. 与第一阶段 Muse（v1 平均 84.9）相比，本批 88.2 略高，但**题目集更难且完全不同**，两个数字不构成能力提升的证据；不同阶段的分数不可并列比较。
5. 与 DeepSeek 同题（Task 16–20）**不能比较**：harness、预算、深度都不同；且 DeepSeek 五题目前尚无独立评价（展示站显示「本运行暂无独立评价」）。
