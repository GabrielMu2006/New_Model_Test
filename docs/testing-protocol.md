# 模型测试隔离与防答案污染协议

本协议面向组织测试的 agent。它是后续测试的执行规范，不表示第一阶段历史测试已经满足这些要求；历史隔离、联网、上下文情况若无证据，一律记为未知。当前仓库没有提供容器调度、网络网关或自动污染检测工具。

## 1. 角色、权限和时间边界

| 角色 | 允许接触 | 不允许的行为 |
|---|---|---|
| 组织者 | 题目、资源白名单、预算、隔离设置、runId | 把参考答案、旧评语或针对结果的提示偷偷加进题目 |
| 被测模型 | 本轮 Prompt、允许的输入资源、自己的输出和允许工具 | 读本仓库、旧结果、其他模型答案、评分或隐藏测试；委托其他 agent 代答 |
| 收集者 | 执行结束后只读导出的成果、日志和环境记录 | 改写成果后当作模型原答案，向执行中会话反馈答案 |
| 评测者 | 封存成果、题目、预先确定的标准、隐藏测试 | 在运行结束前把测试细节或评分反馈给被测模型 |
| 网站维护者 | 经核实的归档和公开副本 | 将生成网站的成功误写为原成果全部通过 |

各被测模型使用独立的新会话。克隆一个已看过其他答案的对话、fork 带历史上下文的 agent、接入同一持久记忆库，均不算干净起点。同一维护 agent 可以负责组织与收集，但不能同时冒充未看答案的参赛者。agent 的显示名称不证明它使用了不同模型。

## 2. 开测前固定实验条件

开始前记录：phaseId、taskId、taskVersion、Prompt SHA-256、允许资源 SHA-256、modelId/实际版本、harness、工具版本、采样设置（若已知）、预算、截止条件、允许联网规则、重复次数和评分规则。

- 逐字发出原始 Prompt。翻译、理论成果和网站后补验收建议不自动属于被测输入；若提供，明确记录并保证各参赛者一致。
- 独立任务默认每题新会话。确需多轮/共享会话测试时，提前声明单独实验组，保存完整追加输入；不能同独立单轮结果无标记比较。
- 时间、token、工具次数、补充轮和超时预算须在开测前确定。不能因为某个模型表现差而临时给予额外帮助。
- 固定重复次数并保留全部运行；基础设施失败、模型失败、拒答、超时分别记录。重试创建新 runId 并关联原失败，不悄悄替换。
- 对比模型接收一致的题目版本、工具、资源和预算；有不可避免的差异时记录并分组。未知设置用 null，不假设默认值。

## 3. 文件系统隔离方案

推荐按**模型 × 任务版本 × 运行次数**创建一次性容器或虚拟机。模型目录只是归档方式，不意味着一个模型的所有运行共用执行目录。

```text
一次性执行环境（仓库外）
/input/prompt.txt       # 本轮逐字输入，只读
/input/assets/         # 预先批准资源，只读；没有则省略
/work/                 # 空白可写工作区，只保留本轮输出
/tmp/                  # 本轮临时文件

组织者环境（被测模型不可访问）
PROMPT/
Test_Results/
website/ docs/ .git/
隐藏测试、评分规则中未公开的部分、历史会话
```

只逐项导出白名单输入，不能先克隆整个仓库再删除可见答案：`.git`、缓存、压缩包和隐藏文件仍可能恢复答案。不得挂载宿主 home、整个项目、SSH/GitHub/云平台凭据、浏览器 profile、其他模型缓存、宿主 Docker socket 或其他运行的目录。

容器使用非特权身份、受限挂载、进程/时间/内存限制；宿主与运行环境之间只通过明确输入和结束后的输出导出接口交换文件。网络默认关闭或经允许域名网关。仅设置环境变量或提示词不构成访问控制。

如果工具只能更换 cwd，或者 agent 仍拥有不受限 shell/宿主文件工具，则标记 `isolation.level = "workspace-only"`，说明具体可见范围，不能标记为强隔离。干净会话也无法消除模型训练阶段可能见过公开题目的风险，应记录为无法验证的训练污染风险。

## 4. 联网与其他工具

- 原题禁止外部库/图片时遵循原题。允许安装依赖不等于允许搜索同题答案。
- 必须联网的任务，预先列出确切域名、用途和方法。例如天气 API 只用于取数据；官方技术文档可以作为统一允许资源。尽量缓存同版本依赖，避免各模型获得不同材料。
- 禁止访问本项目的 GitHub/原始文件/Actions artifacts、VibeTest 网站、其他参赛结果及其镜像；禁止通过搜索摘要、网页缓存、代理、翻译服务、代码搜索、剪贴板、MCP connector、共享聊天记录或其他 agent 间接取答案。
- 不向被测环境提供 GitHub token、私人搜索索引、宿主浏览器登录态或共享向量库。需要模型 API 时由外部 harness 代理，不能把组织者通用凭据挂进去。
- 网络白名单应由环境/网关执行并记录请求，不能只要求模型自觉遵守。隔离完成后，组织者用无敏感内容的探针验证：只读输入不能改、仓库与兄弟工作区不能读、禁止网络目的地不能访问。
- 不能保证严格联网隔离时如实标注 `network-policy-only` 或其他实际限制；该组成绩与有技术隔离保障的组分开描述。

## 5. 执行与封存

1. 建立新 runId；确认输入清单、预算、只读挂载和网络规则。记录探针结果，不通过不能宣称清洁隔离开始。
2. 启动全新会话，只传入允许输入。禁止跨模型共享提示、失败经验、解题代码和隐藏测试反馈。
3. 记录所有追加指令、工具调用、拒绝访问、失败、重试、时间/token 口径；日志含敏感内容时封存完整证据，发布单独脱敏副本。
4. 到达终止条件即停止模型和后台工具，封存输出并计算 SHA-256。保留未完成作品，不在采集阶段修补。
5. 收集者检查输出文件类型、路径、symlink、外链与大小，仅复制允许输出。不要在收集/网站宿主上自动执行 package install、postinstall、测试脚本或 HTML。
6. 评测在另一个全新隔离环境读取封存输出。生产浏览器凭据不可用于测试；演示表单仅填虚构信息。
7. 新的修复实验或提示后改进版本另建 run，关联 `parentRunId`、追加提示及原因；其结果不能冒充首次原始成绩。

## 6. 污染与作弊处理

偷看其他模型答案、自己的同题历史解、参考实现、隐藏测试/评分反馈，或由其他 agent 代答都属于污染。无论故意还是误挂载/共享上下文导致，都需记录。

- 状态取 `clean`（在已声明隔离范围内通过检查）、`suspected`、`contaminated` 或 `unknown`；它不是对训练数据无污染的保证。
- 一旦发现，立即停止该运行并封存事件、发现时间、访问路径/URL、日志位置、已暴露内容范围；不继续用污染上下文取得“清洁”成绩。
- 保留该 run，注明排除原因。汇总清洁结果时排除污染数据并报告排除数量；不删除失败或只公开最好结果。
- 重新测试使用新会话、新环境和新 runId，并关联被替代运行。无法证实是否读到内容时保持 suspected/unknown，不自行写 clean。
- 仅凭代码相似、输出相同或得分异常不能断言作弊；它们是复核信号。需要访问日志、上下文来源或其他证据支持判断。

## 7. 评测独立性和可复现性

评分标准在运行前固定；AI 评测尽量盲评，随机匿名作品顺序，不透露模型身份、其他评委结论或预期排名。评委工具和 Prompt 版本也要留档。若无法盲评，记录限制。

人工评价、AI 评分、自动测试结果分别保存；视觉质量不能只由文件能加载推出。测试报告列出命令、环境、通过/失败/跳过、预期与实际、证据文件、评分方法和时间。不同范围的百分比不可直接平均。

交接字段按 `docs/result-interface.md`。首次测试可以先由组织者给出无未知关键项的测试配置，agent 不得替用户补造模型身份、缺失的原始输入或未经授权的预算。

## 8. 测试工作区目录法（`test-workspace/`）

`test-workspace/` 是测试脚手架：维护 agent 按题目数量生成 `phase-NN/task-NN-<slug>/`，每题目录内含逐字 `prompt.txt`、隔离规则 `AGENTS.md`、可选只读 `assets/`；组织者在该目录逐题开新会话测试；测试结束后汇总并归档到 `Test_Results/`。完整操作见 [`test-workspace/README.md`](../test-workspace/README.md)，被测会话的约束见 [`test-workspace/AGENTS.md`](../test-workspace/AGENTS.md) 与 `_templates/task-AGENTS.md`。

**当前决定（2026-09-09）**：后续阶段测试统一采用本方案，隔离等级记为 `workspace-only`，并配套组织者探针与事后日志审计；不再要求每次另建独立用户或容器。环境级隔离保留为可选升级路径。

**必须如实认识这套方案的效力边界**（本仓库已实测并记录）：

- `AGENTS.md` 属于**策略级约束**，是"请求模型不要看"，不是"模型看不到"。被测会话可以在技术上忽略它；它挡手滑，挡不住有意读取。
- DSH 当前的文件沙箱（`read-only` / `workspace-write` / `danger-full-access`）**只围栏写入与编辑，读取始终直接通过**；macOS 上实际执行的 Seatbelt profile 为 `(allow default)(deny file-write*)…`，白名单只加在写操作上。`dsh-tool-fs` 的配置项只有读取大小上限，没有路径白/黑名单；`read`/`glob`/`grep` 工具不经过沙箱。
- 因此 `workspace-only` 的结论只能写「策略级约束 + 事后审计」，**不得**表述为「强制隔离」「无污染」。
- 可选升级路径（需要更强结论时）：任务目录放到**仓库之外**并配合**独立标准用户**（本仓库已验证：仓库位于权限 700 的 `Documents` 之下，其他标准用户无法进入），或使用**容器/虚拟机**（DSH 可用官方 CLI 的 headless 模式运行，使文件与 shell 能力都落在容器内）。

**统计口径**：`workspace-only` 的运行**可以**计入本阶段汇总，但必须同时满足——① 每个 run 在 `PLAN.md` 与档案中写明 `isolation.level`、网络策略、探针结果与 `contamination.status`；② 事后审计结果与该 run 一并归档；③ 每处展示附带「策略级约束 + 事后审计」标注。缺少审计结果的运行不得计入汇总；审计发现越界的运行记 `suspected`/`contaminated`，排除出汇总并报告数量。

**给被测会话的文件只写绝对规则**：`test-workspace/AGENTS.md` 与 `_templates/task-AGENTS.md` 不得包含「这是策略级约束」「技术上你其实能读到」「去探测边界」之类的表述——那会把越界方法直接写给被测模型；探针必须由**组织者**在开测前执行并把输出存为 `_probe.txt`。关于隔离效力、探针、审计的说明只写在组织者文件（`test-workspace/README.md`、本文件、`PLAN.md`）中。

**事后审计是配套取证，不是替代品**。DSH 会话日志（`session.jsonl.zstd`）记录 `tool/call`、`tool/result`、PTC 模式下 `run_code` 内嵌的 `tools.*` 调用、`sandbox/mode`、`approval/policy` 与推理文本；审计应覆盖工具清单、工作区外绝对路径、网络命令与越界读写，并与组织者写入的各任务 `_probe.txt` 交叉核对。审计结论只能写「未发现越界」，并注明未覆盖渠道（如训练数据、外部搜索无法验证）；审计不得由被测模型自评。

任何使用本方案的运行，必须在 `PLAN.md` 与最终档案中记录：`isolation.level`、实际执行环境、网络策略、探针结果、`contamination.status`（默认 `unknown`/`suspected`，除非有环境级证据支持更强结论）。
