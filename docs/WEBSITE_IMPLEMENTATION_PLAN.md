## 1. 项目位置与目标

网站放在当前 Git 仓库的 `website/` 子目录中，无需另建 GitHub 仓库或项目级文件夹。现有模型产物、Prompt 与 Reviews 保持原路径，网站通过数据索引引用它们。网站源码、依赖与锁文件集中在 `website/`，持续集成位于根目录 `.github/workflows/`，维护说明位于根目录 `docs/`。

禁止在 `website/` 内初始化嵌套 Git 仓库。网站和原始评测档案共用当前仓库的提交历史。

首版目标：让访客能够按模型、任务和阶段浏览结果，阅读原始需求与不同来源的评价，预览实际成果，并分享同题对比链接。现有 15 道题属于第一阶段；新增模型、运行和第二阶段时，不需要重新设计页面或路由。

## 2. 实施范围与完成边界

### 必须完成

- 中英文界面、稳定的详情链接和语言切换。
- 第一阶段 15 个任务、1 个现有模型及每题对应的归档运行。
- 首页、阶段目录/详情、模型目录/详情、任务目录/详情、运行详情、对比页和评测方法页。
- 任务标题和 Prompt 搜索；阶段、模型与任务类别筛选。
- SVG、截图、HTML 应用预览，源码和原始报告链接。
- 同一任务两个运行的并排对比；支持不同模型或同一模型不同运行。
- 分来源展示人工评价、AI 评价与测试证据。
- 数据校验、关键行为测试、自动构建、公开部署和维护文档。
- 用不进入正式站点的测试数据验证新增模型、重复运行和第二阶段扩展。

### 不包含

- 账号系统、评论、在线编辑后台、数据库和收费服务。
- 在线调用模型、自动评测上传代码或允许访客上传执行文件。
- 重做现有 15 项任务、修改模型原始产物或擅自重新评分。
- 无条件可比的综合排行榜、未经核实的排名、虚构模型结果。
- 购买域名、修改 DNS、创建第二个 GitHub 仓库。
- 为展示而重新生成替代原作品的图像。

### 实施权限与停止条件

本计划由启动 Prompt 正式启动后，执行者应连续完成开发、验证、提交、推送及当前仓库内的 GitHub Pages 发布；无需在里程碑之间重复确认。当前仅编写计划的这次操作不启动上述实施工作。

常规技术选择、依赖安装、端口选择、布局细节和修复新网站的问题可自主处理。若账号缺少发布权限、必须购买服务、必须使用新凭据，或用户已有改动与任务产生无法安全消解的冲突，应完成其余可执行部分后报告具体阻碍。不得绕过权限或把未部署写成已完成。

如环境或现有项目规则要求采用其他工具，可替换框架，但必须保留同仓库子目录、静态输出、数据驱动页面和公开访问要求，并在交付文档解释选择。不为框架便利新增服务器或数据库。

默认部署到当前仓库的 GitHub Pages，URL 以 GitHub 实际返回值为准。构建必须支持仓库子路径 `/New_Model_Test/`。使用路径生成函数统一处理语言前缀、资源地址、动态链接与尾斜杠，不在组件里散落硬编码根路径。

## 4. 数据模型与来源规则

| 实体 | 必需信息 | 约束 |
| --- | --- | --- |
| Phase | 稳定 ID、序号、双语名称与说明、任务版本列表 | 当前 `phase-01` 包含 15 个任务 |
| Task | 稳定 ID、版本、双语标题、类别、英文原始 Prompt、中文译文、预期成果、验收项 | 需求修改产生新版本；扩展验收项不能被标为原始硬约束 |
| Model | 稳定 ID、显示名称、版本标识、已知供应方信息 | 未知信息使用 null，不从名称推断能力 |
| Run | ID、模型、任务版本、执行环境、配置、会话信息、指标、产物与版本引用 | 同一模型同一道题允许多次运行；多轮继续不误拆为新结果 |
| Artifact | 类型、入口、资源清单、源码路径、归档提交 SHA、封面与预览能力 | 源码链接固定到归档版本；截图标记生成来源 |
| Review | ID、所评运行/产物版本、来源类型、作者标签、时间、结论、评分方法及证据 | 人工与 AI 评价独立保存，不静默合并 |

Run 中的实际配置与工具环境独立于 Model。记录能确认的 harness（如 DSH）、补充轮、共享上下文、执行时间口径；无法确认的字段保持缺失。

每条测量或结论保留来源路径及章节/行定位；有对应归档提交时生成固定版本 GitHub 链接。任务编号与会话映射使用复盘文件中的显式对应关系，不仅靠文件夹名称推断。

### 首批来源

- 根目录 `15_TEST_PROMPTS_BILINGUAL.md`：原始 Prompt、译文、后补的理论成果和验收建议。
- 模型目录 README 及各任务 README：成果清单、运行说明、已声明测试和限制。
- `Reviews/DeepSeek-V4.1-Flash-Exp-0910-任务评测复盘.md`：耗时、token、调用数、失败重试及会话映射。
- `Reviews/Personal_Review.md`：用户人工观察。
- `Reviews/15-任务完成质量评估.md`：此前 AI 评估及复核记录。

### 展示规则

1. 缺失值使用 null，显示“未记录 / Not recorded”；缺失不等于 0 或失败。
2. 输入、输出、缓存读取 token 分列；总 token 不暗示等价计算量或等价费用。
3. 运行耗时沿用来源口径，不用开始/完成时刻差覆盖累加执行时间。
4. 只有批次总费用时，保留批次金额及来源，不虚构每题费用。
5. 现有截图和复核可能晚于模型初始输出。记录归档版本，不将当前文件未经确认地称为原始生成时的精确版本。
6. 首版优先忠实导入；来源矛盾写入 `source-audit.md`，页面显示相关备注。
7. 任务 06、07 的人工评价与 AI 报告有分歧，应同时展示。其他分歧同样处理。
8. `93.6/100` 和 `15/15` 作为现有 AI 评估报告的结论引用，不能转换成网站自行证明的统一事实。没有来源的分维度评分不能补造。
9. 区分作者自述测试、历史复核记录和本次网站验证。本次验证展示站通过，不代表模型产物的所有功能都已经复验。
10. 未翻译的历史报告保留原文。人工评论的英文翻译标明译文，不能伪装为英文原始评价。

## 5. 页面、路由与交互

推荐公开路由结构为 `/{locale}/...`，所有示例路径均相对于仓库 base path：

| 页面 | 路由示例 | 关键内容 |
| --- | --- | --- |
| 首页 | `/zh/`、`/en/` | 阶段入口、可浏览任务、模型与成果概览 |
| 阶段目录/详情 | `/zh/phases/`、`/zh/phases/phase-01/` | 题目集合、参与模型和数据覆盖 |
| 模型目录/详情 | `/zh/models/`、`/zh/models/{modelId}/` | 模型身份、结果清单、执行记录 |
| 任务目录/详情 | `/zh/tasks/`、`/zh/tasks/{taskId}/` | 原始需求、验收建议、各模型结果 |
| 运行详情 | `/zh/runs/{runId}/` | 成果、指标、评价、来源与版本 |
| 对比 | `/zh/compare/?task=…&left=…&right=…` | 两条运行的成果和指标 |
| 评测方法 | `/zh/methodology/` | 数据定义、来源分类、比较边界 |

根 URL 应进入中文首页或提供清晰语言入口。语言切换保留当前实体及合法查询参数。非法 ID、无效组合和不存在路由显示明确错误及返回入口，不能白屏。

### 视觉方向

以可浏览成果和可操作筛选为第一屏核心。采用适合技术评测的清晰排版、稳定表格和较大成果预览区，不用大幅宣传横幅占据主要空间。使用现有真实截图和 SVG。界面风格应统一，具备可见焦点、合理对比度和移动端布局。

首版只要求一种完成度高的主题，亮暗双主题不是交付前置条件。动态效果克制，尊重减少动态效果偏好。

### 对比规则

- 每次比较同一任务版本的两条运行，支持跨模型或同模型重复运行。
- 左右两侧均显示运行 ID、模型版本、配置和所选产物。
- 实际只有一个可选运行时，显示当前成果和缺少另一结果的状态。
- 两个 iframe 独立控制，不强制同步内部交互。
- 只有双方可用且口径相符的数值才计算差值；配置不同则标注。
- 手机端使用堆叠或选项卡，不强塞两列。
- 选择写入 URL；直接访问和刷新后可恢复。

## 6. 原始产物的预览方式

六项 SVG 用 `<img>` 展示，并提供放大与下载。HTML 成果默认封面，用户点击后才加载隔离预览。提供重新加载、扩大显示、源码和独立查看入口。

iframe 默认使用最少 sandbox 权限。按任务需求配置脚本、下载等能力；不授予任意顶层跳转或弹窗权限。在与展示站同源的嵌入环境中，不同时开启 `allow-scripts` 和 `allow-same-origin`。

若存储或下载能力受隔离限制，先验证产物是否已有降级逻辑；页面准确提示嵌入预览的限制，并提供独立打开入口。新窗口使用 `noopener`。不得通过修改原始模型代码来让预览通过。

首版不依赖新域名。只有未来需要完整可信的跨源交互隔离时，才另行设计独立演示 origin，不擅自创建额外账户或付费基础设施。

多页银行站点必须整体保留相对路由及资源树。天气应用保留真实网络依赖并说明当前数据状态。截图生成使用独立浏览器上下文，必要时滚动触发原页面 reveal，再截图；不能将未触发的空白长页面当作完整封面。
